Guide 31 · Computation

LC-MS feature detection and peak integration

Build mass traces, detect chromatographic signals, and inspect the boundaries, baseline, sampling, and numerical rule behind an integrated area.

FOUNDATIONAL GUIDE · OCT 2026
ENZH
Before you begin: From raw data to reliable results, Profile, centroid & signal processing, Liquid chromatography for MS

Follow a signal through time

An LC-MS run records many spectra as material elutes. A spectral peak is an intensity structure along m/z in one spectrum; a chromatographic peak is an intensity structure along time. Centroiding can summarize spectral peaks, but it does not decide which observations belong together across scans. This Guide begins at that next step: detecting and measuring a signal within one run.

Keep three questions separate: was a signal detected, how was its abundance summarized, and what produced it? A reproducible area does not identify a molecule. Conversely, an identified ion can have an unreliable area because its trace overlaps another signal. Cross-run correspondence comes afterward in alignment and matching.

From spectral observations to mass traces

A mass trace links observations with compatible m/z over neighboring scans. In centWave, candidate regions are collected before chromatographic peak detection; the original method uses wavelets to examine structure at different time scales. [1] This is one implementation, not a definition that every program must follow.

Constructed tolerance example: a symmetric ±5 ppm window centered at m/z 500.0000 extends by 500 × 5 / 1,000,000 = 0.0025, giving 499.9975–500.0025. A centroid at 500.0015 falls inside; one at 500.0040 does not. These invented values demonstrate arithmetic, not recommended settings. A fixed extraction window and an algorithm that updates a trace's center can make different assignments.

A trace can contain two separated elution events at nearly the same m/z. It can also include unresolved contributions. Connecting observations is therefore a candidate-building operation, not proof that they share one chemical origin. Inspect the time profile before treating the entire trace as one integrated peak.

Choose settings that describe the measured peaks

Detection settings encode expectations. The xcms centWave interface distinguishes allowable m/z deviation, a chromatographic width range in seconds, signal-to-noise filtering, and a prefilter requiring enough observations above an intensity threshold. [2] Do not transfer a width value from a different gradient simply because both experiments used LC-MS.

  • Mass tolerance: inspect the observed spread and neighboring signals. A tight rule can break a trace; a broad one can admit interference.
  • Width and sampling: examine narrow and broad peaks across the run. Too few sampled points leave boundaries and shape poorly constrained.
  • Thresholds: check weak real-looking signals as well as noise and blank regions. More reported candidates is not automatically better detection.

One program may report each chromatographic trace as a feature; another may assemble compatible isotope traces and infer charge. OpenMS FeatureFinderMetabo is an example of isotope-aware assembly. [3] Distinct adducts or charge states can still yield multiple entries for one compound. State what a row contains before counting compounds.

An area needs boundaries and a baseline

Peak integration summarizes signal across a selected interval. IUPAC defines chromatographic peak area relative to the baseline. [4] Thus the start, end, background estimate, and numerical method are part of the result, not cosmetic display settings. A common height measurement instead uses the maximum above the chosen baseline.

Software can expose an intensity sum, trapezoidal integration, or other estimators under related quantitative labels. OpenMS documents these as distinct choices. [5] A bare sum does not account for unequal time intervals. Inspect the exported field's meaning rather than assuming every column named “area” has identical units.

Worked example: where did the area come from?

Hypothetical, deliberately sparse teaching trace: relative times are [0, 1, 3, 4] s, measured intensities are [2, 6, 10, 2], and a known constant baseline is 2 intensity units. Subtraction gives [0, 4, 8, 0]. Assume straight lines between observations and integrate over 0–4 s.

The trapezoids contribute (0 + 4) / 2 × 1 = 2, (4 + 8) / 2 × 2 = 12, and (8 + 0) / 2 × 1 = 4. Total area is 18 intensity-unit·s; height is 8 intensity units. The intensity sum is 12, a different summary. Integrating without baseline subtraction gives 26 because the rectangular background contributes 2 × 4 = 8.

Using only 1–3 s keeps area 12 and discards one third of the modeled peak's area. A boundary change alone therefore creates a quantitative change. Adding intermediate points exactly on the assumed straight lines preserves the trapezoidal area but changes a plain intensity sum. Real measurements need adequate sampling; these four points are for transparent arithmetic, not an acquisition recommendation.

Inspect failures that a number conceals

A shoulder may reflect another component, a distorted peak, or noise. Automatically splitting every shoulder creates extra features; integrating every shoulder together can combine contributors. Retain the trace and the algorithm's boundaries, then examine independent evidence before interpreting the number chemically. Deconvolution is a model-based separation, not information created by drawing another boundary.

Check representative isolated, crowded, weak, strong, and truncated signals. Look for boundaries that change erratically between comparable runs, clipped maxima, gaps in sampling, or a broad baseline included as peak. Review rules should apply consistently rather than only to features supporting a desired result. Quantitative calibration and analytical controls address additional questions outside detection itself.

Keep enough information for the next step

Preserve source run and scan links, m/z summaries, original retention times, boundaries, area definition, charge/isotope assignments, and quality flags. Keep software versions and settings with the output. A compact feature table should remain traceable to the measurements that generated it, especially when later matching or manual review changes a row.

Check your understanding

Does one mass trace guarantee one chromatographic peak?

No. Similar m/z observations can contain separate elution events or unresolved contributors. Chromatographic detection must inspect structure along time.

Why is the example's area 18 rather than its intensity sum of 12?

The trapezoidal calculation accounts for unequal time intervals and has intensity × time units. The unweighted sum does neither.

Does detecting twice as many features establish twice as many compounds?

No. Splitting, noise, isotopes, adducts, charge states, and unresolved overlap affect the relationship between feature count and compound count.

References & further reading

  1. Tautenhahn R, Böttcher C, Neumann S. Highly sensitive feature detection for high resolution LC/MS. BMC Bioinformatics. 2008;9:504.

    Primary centWave method paper. Title, authors, year, DOI and abstract verified against PubMed PMID 19040729 on 2026-10-07. Supports candidate mass traces followed by chromatographic wavelet detection; historical comparisons are not presented as current rankings.

  2. xcms. Chromatographic peak detection using the centWave method.

    Official developer documentation inspected 2026-10-07, showing version 4.11.4. Distinguishes trace-building m/z tolerance, chromatographic width in seconds, signal-to-noise and observation-count/intensity prefilters. No documented default is prescribed as a universal setting.

  3. OpenMS. FeatureFinderMetabo documentation.

    Official developer documentation of assembling compatible mass traces into metabolite features and separating elution profiles. Used as an implementation example, not a universal definition or parameter prescription. Documentation inspected 2026-10-06.

  4. IUPAC Gold Book. Peak area in chromatography, entry P04453.

    Official indexed PDF definition checked: area enclosed by peak and baseline. Constructed triangle calculations are original teaching examples, not empirical peak models or prescribed integration methods.

  5. OpenMS. PeakIntegrator class reference.

    Official developer documentation inspected 2026-10-07. Lists intensity summation, trapezoidal and Simpson integration as distinct methods and separate background estimation. Used to establish implementation differences; all numerical traces in these entries are original constructed examples.
