Definition

In LC-MS processing, gap filling revisits source data for a run lacking a detected member of a cross-run feature group. It estimates abundance by extracting signal in an expected m/z–retention-time region. xcms implements this operation and marks the resulting entries as filled. [1] Exact region definitions and acceptance rules are software-dependent.

A simple example

Hypothetical matrix: areas in runs A, B, and C are [80, 100, missing]. A group-informed extraction from C's source trace returns 9. That is a new extraction result from existing measurements. Replacing the missing cell with the observed mean 90 would be a different operation: statistical imputation using the matrix.

The value 9 might include weak analyte signal, background, or interference. The extraction alone cannot choose among those explanations. Review the region and preserve its filled status. If the region has no usable observations, do not manufacture a measured zero simply to complete the row; xcms can leave such entries missing. [1]

Common confusion

Gap filling is not a new acquisition, proof of a chromatographic peak, or a new molecular identification. It uses other runs to decide where to examine the current run, so an incorrect correspondence can direct extraction to the wrong region. A full matrix may therefore contain less trustworthy entries than its appearance suggests.

Check your understanding

Should a filled value automatically be treated exactly like an initially detected peak?

No. Preserve how it was obtained and apply appropriate quality checks. A nonzero integral does not establish equivalent evidence.
